# 点选与悬停改进 · 验证说明

## 改动了什么

楼体仍是**一次实例化绘制**（一个 `InstancedMesh`、一种材质、实例数量不变），
楼的位置、尺寸、颜色均未改动。所有变化都在事件与状态层：

| 文件 | 变化 |
| --- | --- |
| `src/lib/picking.ts`（新增） | 纯函数判定模块：8 像素规则、按下/抬起同一实例、行程守卫、滚轮守卫、空白点击判定 |
| `src/scene/useCanvasPicking.ts`（新增） | 画布级按下/行程/滚轮状态，供楼体与“点空白”两条路径共用同一套规则 |
| `src/scene/Buildings.tsx` | 悬停改为**逐帧射线检测**；点击走 `resolveClick`；指针样式随命中更新 |
| `src/scene/CityScene.tsx` | 自动旋转集中到一处管理，**按住指针期间暂停**；`onPointerMissed` 走 `resolveMiss` |
| `verify.html` + `src/verify/`（新增） | 可本地运行的验证页（见下） |

### 根因与对策

1. **点不中 / 点错楼（相机贴近、楼群密集时最明显）**
   城市默认在自动旋转，而旋转只在“抓住相机”时才停止——普通点击不会停。
   于是按下时射线命中 A 楼，抬起（约 100–300ms 后）时楼已转走，射线命中
   B 楼或天空，`instanceId` 对不上，点击被丢弃或落空。现在**按住指针期间
   暂停自动旋转**，松手恢复，按下与抬起看到的是同一个画面。

2. **拖动旋转后误弹出卡片**
   浏览器在拖动结束后仍会派发 `click`。原有 8 像素规则保留，另加两条：
   - **行程守卫**：按下期间指针累计移动超过 8px，即使绕一圈回到原点
     （净位移为 0）也不算点击；
   - **滚轮守卫**：按住期间发生过滚轮缩放，抬起不算点击。
   “点空白收起卡片”用同一套规则，拖动/缩放不再误收起。

3. **悬停高亮滞后**
   原来悬停只在 `pointermove` 事件里更新，相机在指针静止时转动
   （自动旋转、阻尼、飞行动画）就会高亮错楼。改为**每帧用当前指针位置
   做一次射线检测**，高亮、提示条、`pointer` 指针样式始终跟随实际命中的楼；
   移出楼群、指针离开画布或移到 HUD/面板上时立即清除。

### 射线 / 包围体策略的取舍

保留 three.js 对 `InstancedMesh` 的**精确盒体逐实例求交**，没有放大包围盒、
没有引入拾取代理网格。排查后确认“相机贴近时命中不稳”并非求交精度问题，
而是上述第 1 条（按下与抬起之间相机仍在动）和第 3 条（悬停不随相机更新）
造成的表象；放大包围盒只会在密集楼群里制造更多“点错楼”，因此不采用。
已知边界：若在拖动后的阻尼余晖（约零点几秒）内按下，相机仍会微动，
此时点击可能被判为非同楼而丢弃——这是保守方向（宁可不选，不可错选）。

## 如何本地验证

```bash
npm install
npm run dev        # 默认 3210 端口
```

### 自动测试（两栋相邻楼 + 空白区域）

浏览器打开 <http://localhost:3210/verify.html>，点击右侧**“运行全部自动测试”**。
页面复用与正式城市完全相同的 `<Buildings>` 与 `useCanvasPicking`，
场景为两栋相邻的楼（alpha / beta）和周围大片空白，自动注入合成指针事件，
覆盖四类路径、共 8 条断言：

- **T1 正常点选**：按下/抬起同一栋楼 → 选中
- **T2 拖动后不选中**：T2a 拖动旋转后抬起；T2b 拖走又拖回原位（净位移 0）；
  T2c 按住期间滚轮缩放
- **T3 点到空白**：先选中再点空白 → 卡片收起
- **T4 悬停进出**：进入楼 → 高亮 + 手型；移到空白 → 清除；离开画布 → 清除

结果逐条显示 ✅ / ❌ 与实测值，顶部汇总“通过 n / 8”。

### 手动观察

- 在 `verify.html`：单击楼 → 右侧面板“当前选中”变化；拖动后松开 → 不变；
  点空白 → 清空；鼠标在楼间移动 → “当前悬停”与线框高亮实时跟随。
- 在主页 <http://localhost:3210/>：城市自动旋转时直接单击某栋楼 →
  能稳定选中并弹出卡片；拖动旋转后松开 → 不误弹卡片；点空白 →
  收起卡片并把旋转中心交还城中心；Esc 关闭、R 随机行为不变。

`npm run build` 会同时打包 `index.html` 与 `verify.html`，可用于类型与产物检查。
